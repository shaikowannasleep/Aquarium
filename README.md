## One portfolio, three experiments

This repository is the public hub for three related projects. They share a
question: **how much life can emerge from a small set of local rules?**

| Project | What it demonstrates | Play | Source |
|---|---|---|---|
| 🐠 **Aquarium** | GitHub repositories become a live boids ecosystem; motion is baked to SVG/SMIL | [Open](docs/apps/aquarium/) | [Code](apps/aquarium/) |
| 🌊 **Abyssal Dive** | Boids + flow-field pathfinding; the fish follow water, not a hidden map | [Open](docs/apps/abyssal-dive/) | [Code](apps/abyssal-dive/) |
| ✨ **Lumen** | Boid rules become the verbs of a playable ad: cohesion, separation, alignment | [Open](docs/apps/lumen-playable/) | [Code](apps/lumen-playable/) |

---

## Why they belong together

The projects are intentionally different products built on a common technical
language:

- **Emergence:** separation, alignment and cohesion produce behaviour instead
  of a leader script.
- **Performance:** typed arrays, spatial hashing, counting sort and zero
  external requests keep the experiments small and fast.
- **Readable systems:** the fish do not receive a magical global instruction.
  In Abyssal Dive, safety is encoded in a flow field generated by the water;
  in Aquarium, repository data becomes the world state.
- **Playability:** the algorithm is not only a visual effect. It creates the
  choices, pressure and replay value.

## Repository map

```text
apps/
├── aquarium/              # GitHub data -> headless boids -> animated SVG
├── abyssal-dive/          # Canvas game: lamp, hunter, flow field, depth panel
└── lumen-playable/        # Self-contained playable ad

docs/
├── index.html             # Portfolio hub / GitHub Pages landing page
└── apps/                  # Static playable builds for each project

tools/                    # Hub-level scripts and future shared tooling
```

Each app remains independently readable and buildable. The monorepo is a
navigation and presentation layer, not a forced rewrite of three working
experiments.

## Local usage

```bash
# Serve the hub and all playable builds
python3 -m http.server 8090 -d docs
# open http://localhost:8090

# Aquarium
cd apps/aquarium
node tools/bake-svg.js shaikowannasleep
node tools/build-pages.js shaikowannasleep

# Abyssal Dive
cd apps/abyssal-dive
node build.js
node test/flowfield.test.js
node test/level.test.js
# The long bot/frenzy tests are manual-only.

# Lumen
cd apps/lumen-playable
node test/headless.js
node build.js
```

The generated `docs/apps/*/index.html` files are self-contained and can also
be opened directly with `file://`.

## Selected technical proof

| Signal | Evidence |
|---|---|
| Spatial optimisation | Aquarium measured a 98% reduction in pair tests at 1000 agents |
| Shared-agent pathfinding | Abyssal Dive rebuilds a multi-source flow field on demand; one field serves the entire school |
| Ad constraints | Lumen is a single HTML file with 0 external requests |
| Deterministic systems | Seeded levels and setup make replay/debugging reproducible |
| Design honesty | Fast correctness tests run by default; slow bot balance tests are manual-only |
